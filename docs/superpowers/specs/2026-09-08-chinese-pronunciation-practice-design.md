# Chinese Pronunciation Practice Design

## Goal

在“中文读”复习模块中加入跨平台语音练习：用户点击麦克风朗读当前中文条目，系统判断是否读对；首次读对自动判为“熟练”并播放儿童友好的庆祝动画，首次读错自动判为“彻底陌生”并提供重试、标准读音和辅助词练习。

## Scope

- 语音识别覆盖中文读模块中的单字、词语和短句。
- 中文写、英文读、英文拼不显示语音练习控件。
- 中文读模块关闭现有复习倒计时；其他模块的倒计时行为保持不变。
- 单字条目下方始终显示三个简单常用词语，目标字在词语中高亮，但辅助词的字号、颜色和间距弱于主字。
- 词语和短句条目不显示三个辅助词。
- 单字多音字的任一常见读音均视为正确；标准示范采用最常用读音。
- 音频不写入本地存储、Supabase 或应用日志。

## Chosen Technical Approach

采用“浏览器短录音 + Vercel Serverless + 阿里云百炼语音能力”的非流式方案。

浏览器原生 Web Speech API 虽然延迟低，但在 iOS PWA、Safari、Android 和桌面浏览器之间支持与行为不一致，不能作为跨平台主方案。流式 WebSocket 识别延迟更低，但需要临时令牌、音频分片、重连和复杂状态管理，不适合当前规模。

前端使用 `navigator.mediaDevices.getUserMedia`、`MediaRecorder` 和 Web Audio API：

- 用户第一次点击麦克风时触发浏览器系统权限请求；
- 授权后在当前中文读模块会话内复用同一 `MediaStream`，不重复弹出应用确认或主动重新申请权限；
- 离开中文读模块或组件卸载时停止所有音轨；
- 浏览器权限提示无法被应用绕过，如果用户已授权，浏览器通常不会重复询问。

服务端新增独立 API 适配层，继续通过 `QWEN_API_KEY` 调用百炼：

- `/api/assess-pronunciation`：接收短音频和目标中文文本，返回结构化判定；
- `/api/generate-pronunciation-examples`：为单个汉字生成三个简单、常用且互不重复的词语；
- `/api/synthesize-pronunciation`：把一个中文文本转换为可播放音频。

具体模型名通过服务端常量或环境变量集中配置，前端不接触密钥或供应商协议。

## Component Boundaries

### `ReviewSession`

负责判断当前是否为中文读模式，并把当前 `Word`、评分回调和切词生命周期传给语音练习组件。它继续拥有复习队列和 SM-2 提交逻辑，但不直接管理录音器、静音检测或音频播放细节。

### `PronunciationPractice`

新增独立组件，负责：

- 麦克风、停止、重试和“听正确读音”按钮；
- `idle`、`requesting-permission`、`listening`、`assessing`、`correct`、`incorrect`、`error` 状态；
- 首次语音评分锁；
- 正确提示和烟花动画；
- 错误后的练习流程；
- 切换条目时清理录音、播放和延迟跳转。

### `speechRecorder`

新增前端录音工具，封装：

- 获取和复用麦克风流；
- 选择浏览器支持的 `MediaRecorder` MIME 类型；
- 收集音频分片；
- 使用 `AnalyserNode` 检测用户开始说话后的静音；
- 再次点击停止和最长录音超时；
- 释放音轨与音频上下文。

组件只消费明确的 `start() / stop() / dispose()` 接口，不直接操作底层浏览器对象。

### `pronunciation`

新增前端服务模块，封装三个 API 请求、超时、响应校验、音频 Blob URL 创建与释放。组件不直接拼装请求或解析供应商响应。

### Pure Policy Helpers

把以下规则抽为纯函数，便于 Node 测试：

- 是否为单个汉字；
- 识别文本标准化；
- 首次尝试对应的评分；
- 后续重试不重复评分；
- 三个辅助词必须包含目标字、去重且按长度与常用程度过滤；
- 语音播放序列为“目标字 → 辅助词一 → 辅助词二 → 辅助词三”。

## Data Model

在 `Word` 增加：

```ts
pronunciationExamples: string[];
```

规则：

- 仅单字中文条目使用；
- 旧本地数据和旧云端数据缺失时默认 `[]`；
- Supabase `words` 表增加 `pronunciation_examples text[] not null default '{}'`；
- `rowToWord`、`upsertWord`、本地兼容读取和数据共享 RPC 同步该字段；
- 生成成功后立即更新当前队列并调用现有 `repo.upsertWord` 持久化；
- 已有三个有效词语时不重复调用生成接口。

持久化辅助词可以让以后复习立即显示，避免每次进入都等待 AI 生成。

## User Flow

### Showing a Chinese Item

1. 中文读模块挂载时不启用倒计时。
2. 如果当前条目是单个汉字：
   - 已有 `pronunciationExamples` 时立即显示；
   - 没有时后台生成，区域显示弱化的“正在准备词语…”；
   - 生成完成后显示三个词语，并高亮每个词中的目标字。
3. 多字条目不请求也不显示辅助词。

### Recording

1. 用户点击麦克风。
2. 首次使用时浏览器请求麦克风权限，成功后在本次模块会话复用音频流。
3. UI 显示“正在听…”和轻量脉冲效果。
4. 用户可再次点击停止；检测到已说话后连续约 800ms 静音也自动停止。
5. 最长录音约 6 秒，达到上限后自动提交。
6. 前端把音频和当前目标文本发送到评估 API。

### First Attempt Correct

1. 为当前 `word.id` 记录“首次语音评分已提交”，防止重复评分。
2. 显示“读对了”。
3. 播放不依赖第三方动画库的轻量 CSS 烟花效果。
4. 约 1.2 秒后通过现有评分流程提交 `mastered` 并进入下一项。
5. 如果用户在延迟期间切词或离开模块，取消该自动提交。

### First Attempt Incorrect

1. 为当前 `word.id` 记录“首次语音评分已提交”。
2. 立即通过现有评分流程提交 `forgotten`，但停留当前项。
3. 显示“再试一次”和“听正确读音”。
4. 同时在后台预取目标字和三个辅助词的示范音频。
5. 后续点击“再试一次”仍可重新识别并显示“这次读对了”或“再试一次”，但不再提交任何评分。

### Listening to Correct Pronunciation

1. 用户点击“听正确读音”。
2. 依次播放目标字、辅助词一、辅助词二、辅助词三。
3. 播放过程中高亮当前正在播放的文本。
4. 切词、重新录音、再次点击播放或离开模块时，立即停止旧播放序列并释放临时音频 URL。

对于多字条目，错误后只播放当前完整条目的标准读音，不生成或播放三个辅助词。

## Pronunciation Assessment

评估 API 接收：

- 当前目标文本；
- 浏览器生成的短音频；
- 音频 MIME 类型。

服务端限制请求方法、文本长度、音频类型和最大体积，然后调用支持中文音频理解或语音识别的模型，要求返回严格 JSON：

```ts
interface PronunciationAssessment {
  correct: boolean;
  recognizedText: string;
  acceptedReading: string | null;
}
```

判定原则：

- 单字允许任一常见读音；
- 词语和短句忽略空白及常见中英文标点后比较完整内容；
- 不因为背景噪声、模型无结果或低置信度而判错，这些情况返回可重试错误；
- 技术错误永远不触发复习评分。

服务端负责把供应商响应约束为稳定的应用响应，供应商原始结果不直接传给前端。

## Permission and Interruption Policy

- 不增加应用自己的权限确认弹窗。
- 只由真实的用户点击触发 `getUserMedia`，满足浏览器安全要求。
- 获得权限后复用音频流，避免每个字重新初始化麦克风。
- 权限被拒绝时显示一次简短说明和“重新尝试”按钮，不循环弹窗。
- 页面隐藏、切换复习项、切换模块或卸载时停止录制和播放。

## Error Handling

- **浏览器不支持录音**：显示“当前浏览器不支持语音练习”，保留原有手动评分功能。
- **权限拒绝**：显示如何在浏览器设置中开启麦克风，不提交评分。
- **未检测到有效语音**：提示“没有听清，请再试一次”，不提交评分。
- **录音过短或文件过大**：前端阻止无效提交；服务端再次校验。
- **识别超时或服务异常**：显示重试按钮，不提交评分。
- **辅助词生成失败**：不阻塞主复习流程，显示重新生成入口。
- **语音合成失败**：保留文字辅助词，提示重新播放。
- **重复点击**：录音、评估和播放阶段禁用冲突操作；每个 `word.id` 的首次语音评分最多提交一次。
- **陈旧响应**：每次识别、生成和播放使用请求编号；切词后忽略旧响应。

## Visual Design

- 麦克风按钮位于主字下方、辅助词上方，使用清晰的麦克风图标和文字状态。
- 三个辅助词横向排列，窄屏时允许换行；字体明显小于主字，使用中性弱化颜色。
- 目标字使用现有主题强调色和较高字重，不改变词语整体可读性。
- 正确反馈使用绿色文字、短暂缩放和少量 CSS 烟花粒子，持续约 1.2 秒，不遮挡整个页面，不引入动画依赖。
- 错误反馈使用温和文案“再试一次”，避免惩罚性视觉效果。
- 所有状态通过文字表达，不只依赖颜色或动画。

## Testing

### Pure Logic

- 单个中文汉字检测；
- 标点和空白标准化；
- 首次正确映射为 `mastered`；
- 首次错误映射为 `forgotten`；
- 已评分后的重试不返回评分；
- 辅助词包含目标字、去重并限制为三个；
- 播放顺序正确。

### Recorder

- 支持的 MIME 类型选择；
- 手动停止；
- 说话后静音自动停止；
- 未说话时不因静音立即提交；
- 六秒硬超时；
- `dispose()` 停止音轨和音频上下文。

### API

- 非 POST 请求、缺失文本、非中文目标、无音频、非法 MIME 和超大音频被拒绝；
- 正常供应商响应映射为稳定 JSON；
- 无语音、超时、非法供应商 JSON 和上游错误返回明确状态；
- 辅助词生成结果经过包含目标字、去重和数量校验；
- 语音合成只接受长度受限的中文文本。

### Integration

- 只有中文读显示语音组件；
- 中文读倒计时为零，其他模式保持配置值；
- 单字显示三个辅助词，多字条目不显示；
- 首次正确只提交一次 `mastered`，动画后进入下一项；
- 首次错误只提交一次 `forgotten` 并停留当前项；
- 重试不重复评分；
- 切词会取消录音、播放、请求结果和延迟跳转；
- 权限或网络错误不提交评分。
